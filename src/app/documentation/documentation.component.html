Overview

The LLM Catalog is a real-time catalogue of every large language model available through OpenRouter. It was built to help ASU decision-makers, researchers, and engineers quickly evaluate, compare, and select the right AI model for any task — without wading through scattered API documentation.

All model data is fetched live from the OpenRouter API — prices, capabilities, and provider availability are always up to date.

Getting Started

No login or API key is needed to browse the catalog. Just open the app and you'll see the full list of available models loaded automatically.

  1. 1
    Browse the catalog

    The home page shows all models as cards. Each card displays the provider logo, model name, modality badge, capability chips, context window size, and pricing at a glance.

  2. 2
    Use the search bar

    Type any part of a model name or ID (e.g. gpt, claude, llama) to instantly filter the list.

  3. 3
    Apply filters

    Use the toolbar below the search bar to narrow results by modality, pricing, context length, capability, or provider.

  4. 4
    Open a model's detail page

    Click any card to open its full detail page, which shows pricing breakdown, capabilities, architecture info, and the complete list of hosting providers with uptime statistics.

Capability Badges

Each model card and detail page shows coloured capability chips. Here's what each one means:

🔧 Tools The model supports function calling / tool use — it can invoke external APIs, run code, or call structured functions defined in your prompt. Essential for agentic workflows.
👁 Vision The model accepts image inputs alongside text. You can send screenshots, diagrams, or photos and ask questions about them.
🌐 Web The model has live web search access — it can retrieve up-to-date information from the internet at inference time instead of relying solely on its training data.
💸 Discount The model is flagged as having discounted pricing on OpenRouter — typically promotional or batch rates significantly below standard tier.

Model Detail Page

Click any model card to open its dedicated detail page. It contains five information panels:

Hero header
Provider logo, model name, modality, release date, and a strip of key statistics — context window, pricing per million tokens (input & output), max output tokens.
Capabilities
All supported capabilities with visual badges and explanatory tooltips (hover the ⓘ icons).
Architecture
Modality, tokenizer type, instruction following type, and quantisation details where available.
Description
The model's official description from the provider, rendered in full.
Provider endpoints
Every OpenRouter endpoint hosting this model — with its provider logo, context limit, max output, input price, output price, and 30-minute & 24-hour uptime percentages colour-coded green/yellow/red.

Providers

OpenRouter aggregates models from 60+ providers. Provider logos are resolved automatically using the logo.dev brand logo API with Google Favicons as a fallback, and a deterministic coloured-initial avatar as a final fallback — so every provider always has a visual identity.

The Multi-provider toggle in the filter bar lazy-loads endpoint counts for all models (up to 10 concurrent requests) and then filters to only models available from more than one provider. This is valuable when:

  • You want pricing competition — different providers charge different rates for the same model.
  • You need reliability redundancy — if one provider is down, another can serve the same model.
  • You are evaluating SLA options — uptime percentages differ across providers.

FAQ

Where does the data come from?

All model data is fetched live from the OpenRouter /api/v1/models endpoint. Provider endpoint details (pricing, uptime, context) come from /api/v1/models/:id/endpoints.

Do I need an API key to use this catalog?

No. The catalog only reads public OpenRouter metadata endpoints that do not require authentication. No API key is stored or transmitted.

Why does the Multi-provider toggle take a few seconds to load?

The main model list doesn't include per-model endpoint counts. When you enable Multi-provider mode, the app fetches the endpoint detail for every model (up to 10 requests in parallel) to determine how many providers host each one. This is a one-time load per session.

What does the context window number mean?

Context window (measured in tokens) is the maximum amount of text — both your input and the model's output — that the model can process in a single call. Larger context windows are needed for long documents, codebases, or extended conversations. ~750 words ≈ 1 000 tokens.

What is a "provider" vs. a "model"?

A model is the AI (e.g. Meta Llama 4 Maverick). A provider is the company hosting and serving that model via an API (e.g. Fireworks, Together, Groq). Multiple providers can host the same model, often at different prices and with different uptime SLAs.

How is pricing displayed?

Input and output prices are shown in USD per million tokens. A price of $0.00 means the model is currently free on that provider endpoint. Prices are sourced directly from OpenRouter and may change without notice.

Can I link directly to a model?

Yes — the app uses hash routing. Every model detail page has a stable URL in the format /#/model-id/here that you can bookmark or share.

LLM Catalog Documentation

A straightforward hub for evaluating and choosing large language models, powered by live data from the OpenRouter API.

Overview

The LLM Catalog is a real-time catalogue of every large language model available through OpenRouter. It was built to help ASU decision-makers, researchers, and engineers quickly evaluate, compare, and pick the right AI model for any task, without wading through scattered API documentation.

Key features at a glance:

  • Instant Search — full-text search across model names and IDs in real time.
  • Smart Filters — filter by modality, pricing, context window, capabilities, and provider.
  • Capability Badges — at-a-glance chips for Tool Use, Vision, Web Search, and Discount pricing.
  • Provider Insights — see how many independent providers host each model, with uptime and pricing per endpoint.
  • Latest Additions — a live sidebar tracks models added in the last 14 days.
  • Provider Logos — real brand logos across cards, filters, and detail pages.
All model data is fetched live from the OpenRouter API, so prices, capabilities, and provider availability are always current.

Getting Started

No login or API key is needed. Just open the app and the full list of available models loads automatically.

  1. Browse the catalog — the home page shows all models as cards. Each card displays the provider logo, model name, modality badge, capability chips, context window size, and pricing at a glance.
  2. Use the search bar — type any part of a model name or ID (for example gpt, claude, or llama) to instantly narrow the list.
  3. Apply filters — use the toolbar below the search bar to narrow results by modality, pricing, context length, capability, or provider.
  4. Open a model's detail page — click any card to open its full detail page, which shows a pricing breakdown, capabilities, architecture info, and the complete list of hosting providers with uptime stats.

Capability Badges

Each model card and detail page shows coloured capability chips. Here is what each one means:

  • Tool Use — the model supports function calling. It can invoke external APIs, run code, or call structured functions you define. Essential for agentic workflows.
  • Vision — the model accepts image inputs alongside text. You can send screenshots, diagrams, or photos and ask questions about them.
  • Web Search — the model has live web search access, pulling up-to-date information at inference time rather than relying only on its training data.
  • Discount — this model is offered at a discounted price on OpenRouter, typically a promotional or batch rate below the standard tier.

Model Detail Page

Click any model card to open its dedicated detail page. It is split into five sections:

  • Hero header — provider logo, model name, modality, release date, and a row of key stats including context window size, input and output pricing per million tokens, and max output tokens.
  • Capabilities — all supported capabilities shown as visual badges. Hover the ⓘ icons for plain-English explanations.
  • Architecture — modality, tokenizer type, instruction-following type, and quantisation details where available.
  • Description — the model's official description from the provider, shown in full.
  • Provider endpoints — every OpenRouter endpoint hosting this model, showing context limit, max output, input and output pricing, and uptime over the last 30 minutes and 24 hours. Uptime is colour-coded green, yellow, or red.

Providers

OpenRouter aggregates models from 60+ providers. Provider logos are pulled from the logo.dev brand logo API, with Google Favicons as a backup and a coloured-initial avatar as a last resort, so every provider always has a visual identity.

The Multi-provider toggle in the filter bar loads endpoint counts for all models on first use (up to 10 requests in parallel) and then filters to only models hosted by more than one provider. This is useful when:

  • You want pricing competition. Different providers often charge different rates for the same model.
  • You need a reliability backup. If one provider goes down, another can still serve the same model.
  • You are comparing SLA options. Uptime percentages can vary significantly across providers.

Use Cases

  • Research and Academia — find models with large context windows (128k+) for long-document analysis. Filter by Vision to identify multimodal models for image-based research tasks.
  • Enterprise Procurement — compare pricing across providers for the same model. Use the Multi-provider filter to find models with redundant hosting for high-availability production requirements.
  • Developer Integration — filter by Tool Use to find models suited for agentic pipelines and function-calling workflows. Check endpoint uptime before committing to a provider.
  • Cost Optimisation — filter by Free or Discount pricing to find cost-effective alternatives. Sort by price ascending to surface the cheapest options for a given capability set.
  • Real-time Applications — filter by Web Search to find models that can access live information. Great for news summaries, market research, or any question that needs a current answer.
  • Model Benchmarking — use the Latest Additions sidebar to track newly released models. Open their detail pages to compare architecture, context limits, and pricing before running evaluations.

FAQ

Where does the data come from?

All model data is fetched live from the OpenRouter /api/v1/models endpoint. Provider details like pricing, uptime, and context length come from /api/v1/models/:id/endpoints.

Do I need an API key to use this catalog?

No. The catalog only reads public OpenRouter metadata endpoints that do not require authentication. No API key is stored or sent anywhere.

Why does the Multi-provider toggle take a few seconds?

The main model list does not include per-model endpoint counts. When you turn on Multi-provider mode, the app fetches endpoint details for every model in batches of 10 to find out how many providers host each one. This only happens once per session.

What does the context window number mean?

The context window (measured in tokens) is the maximum amount of text the model can handle in a single call, including both your input and its response. Larger windows are needed for long documents, large codebases, or extended conversations. Roughly 750 words is about 1,000 tokens.

What is the difference between a "provider" and a "model"?

A model is the AI itself, for example Meta Llama 4 Maverick. A provider is a company that hosts and serves that model via an API, such as Fireworks, Together, or Groq. Multiple providers can host the same model, often at different prices and with different uptime records.

How is pricing shown?

Input and output prices are displayed in USD per million tokens. A price of $0.00 means the model is free on that endpoint. Prices come directly from OpenRouter and can change at any time.

Can I link directly to a model?

Yes. The app uses hash routing, so every model detail page has a stable URL like /#/model-id/here that you can bookmark or share with colleagues.
